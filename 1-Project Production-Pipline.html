# Katman Bileşen Teknoloji Durum Ne Yapılacak — Somut Kazanım / Portfolyo Değeri
KATMAN 1 — VERİ KAYNAĞI
1a Veri Kaynağı OPC-UA Server asyncuaProsys Sim Vardı Temperature, pressure, vibration node'ları. 3 sanal ekipman. Gerçekçi noise ekle. Modern SCADA protokolü. Dragon Oil / Petronas standartı.
1b Veri Kaynağı Modbus TCP Server pymodbusModRSsim2 P1'den eklendi Aynı 3 ekipmanı Modbus Holding Register olarak da yayınla. OPC-UA ile paralel çalışır. Function Code 03 ile okunur. Türkmengaz/Nebit eski sistemleri. "Hem eski hem yeni protokolü biliyor" kanıtı.
KATMAN 2-3 — PROTOKOL VE KOLEKSİYON
2 Protokol OPC-UA Client asyncua Vardı Node subscription ile event-driven veri çekme. 1s interval. Wireshark ile trafik analizi yap. Modern endüstriyel standard. Paket analizi adayları ayıran faktör.
3 Collector Python Bridge asyncuapymodbus Genişletildi OPC-UA subscription + Modbus polling birleştir. Her iki kaynaktan JSON üret. Ortak veri formatı: {source, equipment_id, tag, value, timestamp, quality}. Çift protokol yönetimi. Gerçek entegrasyon senaryosu.
KATMAN 4-5 — MESSAGING
4 Broker MQTT Broker Eclipse Mosquitto Vardı Topic yapısı: plant/equipment_id/tag. QoS 1 (at-least-once). Docker container ile çalıştır. Event-driven mimari. IIoT standart mesajlaşma katmanı.
5 Consumer MQTT Subscriber paho-mqtt Vardı Wildcard subscribe: plant/#. JSON parse. Batch buffer: 100 mesaj veya 5 saniye dolunca yaz. Streaming ingestion. Batch/stream farkını pratikte uygulama.
KATMAN 5b — VERİ TEMİZLEME (P1'DEN EKLENDİ)
5b Temizleme Data Cleaning Pipeline pandasnumpy P1'den eklendi Consumer → DB arasına cleaning step ekle: (1) NaN / -1 / 9999 değerlerini handle et, (2) Z-score ile anlık spike tespit, (3) 3-nokta rolling median ile gürültü filtresi. Temiz ve ham veriyi ayrı tablolara yaz. Production sistemlerde sensör arızaları çok yaşanır. "Veriyi temiz tutuyor" mülakatta güçlü kanıt.
KATMAN 6-7 — VERİTABANI
6 Veritabanı TimescaleDB TimescaleDBDocker Vardı PostgreSQL + TimescaleDB extension. Docker container. Hypertable: chunk_time_interval 1 gün. Endüstriyel zaman serisi depolama. Plain PostgreSQL'den 10-100x hızlı sorgu.
7 Schema 3-Tablo Schema sensor_readingsequipment_metadataalarm_events Genişletildi Orijinal: sadece hypertable. Ekle: equipment_metadata (id, name, location, protocol, limits) ve alarm_events (hypertable). Index: equipment_id + time. TimescaleDB retention policy: raw 30 gün, compressed 1 yıl. Normalize schema tasarımı. Retention policy. Mülakatta "schema nasıl tasarladın?" sorusuna tam cevap.
KATMAN 8-11 — GÖRSELLEŞTİRME VE ANALİZ
8 Dashboard Grafana Grafana OSS Vardı TimescaleDB datasource. 4 panel: trend, realtime, equipment status, alarm history. ISA-101 renk kodları. SCADA benzeri izleme. Görsel portfolyo kanıtı.
9 Analiz Python Analytics pandasnumpy Vardı Saatlik/günlük aggregate hesapla. Moving average, std deviation, min/max. Scheduled job (APScheduler). Veri içgörüsü. Veri analisti rollerinde temel beklenti.
10 Anomali ML Detection scikit-learn Vardı Isolation Forest ile anomali skoru. Threshold: contamination=0.05. Anomali tespiti sonucu alarm_events tablosuna yaz. README: "model production'da nasıl güncellenir?" Predictive maintenance kanıtı. Data science + OT kesişimi nadir ve değerli.
11 Alarm Alert System Grafana AlertMQTT Vardı Grafana: threshold alert → MQTT publish. Python consumer: alarm_events'e yaz, ISA-18.2 state machine çalıştır (unacked→acked→RTN). Deadband: eşik ±%3. Gerçek SCADA alarm davranışı. ISA-18.2 standardı.
KATMAN 12-15 — ALTYAPI VE DOKÜMAN
12 Container Docker Docker Compose Vardı docker-compose.yml: TimescaleDB + Mosquitto + Grafana. Python servisleri native çalıştır (8GB RAM için). Detay: Docker stratejisi tabında. Production mindset. "Sistemi başka makineye taşıyabilir misin?" sorusuna cevap.
13 Logging Gözlemlenebilirlik Python logging Vardı Structured logging: JSON formatında. Log seviyeleri: DEBUG/INFO/WARNING/ERROR. Her servis için ayrı log dosyası. Log rotation: 10MB max, 5 backup. Debug kabiliyeti. "Saha sorunu nasıl çözersin?" sorusuna cevap.
14 Reliability Fault Tolerance tenacityasyncio Vardı Exponential backoff retry: 1s, 2s, 4s, 8s, max 60s. OPC-UA / MQTT kopma durumunda otomatik reconnect. Circuit breaker: 5 ardışık hata → 30s bekle. Endüstriyel dayanıklılık. "Network koparsa ne olur?" sorusuna cevap.
15 Doküman README + Mimari Markdowndraw.io Genişletildi Orijinal: mimari diyagram + nasıl çalıştırılır. P1'den ekle: (1) Purdue Model katman haritası, (2) Batch vs Streaming açıklaması, (3) OT güvenlik threat modeli (MITRE ATT&CK ICS), (4) Modbus vs OPC-UA karşılaştırması. İşe alınmayı sağlayan şey. Kritik değişiklik: Bridge (Katman 3) artık hem OPC-UA hem Modbus'tan veri alıyor ve ortak JSON formatına dönüştürüyor. Downstream katmanlar hangi protokolden geldiğini bilmek zorunda değil — bu gerçek endüstriyel entegrasyon mimarisi.
Orijinal plan "her şeyi Docker'a koy" dedi. 8GB RAM + 2Mbit internet için bu yanlış strateji. TimescaleDB + Mosquitto + Grafana + 4 Python container = ~2.5GB RAM + Docker daemon ~300MB = toplam ~2.8GB. Geliştirme sırasında IDE + tarayıcı ile birlikte 5-6GB'a çıkar. Çözüm: hibrit yaklaşım.
